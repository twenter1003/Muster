미뤄도 된다고 했지만 스키마에 영향이 있어 지금 결정했다:

**A-6** DORA 입력은 **GitHub 이벤트에서 도출**한다. `DEPLOYMENT_EVENTS` 신설, `deployment_status`·`workflow_run` 웹훅으로 적재. 배포빈도=success 수, 리드타임=`committed_at`→`occurred_at`, 변경실패율=failure 비율, MTTR=failure→다음 success. 각 프로젝트에 리포팅 코드를 심는 방식은 채택률이 낮으면 지표가 비므로 제외했다. **등급 구간도 확정**(Part 2 §6.4 표). 이벤트 0건인 지표는 평균에서 제외, 4개 모두 없으면 스코어 미산출.

**A-5·A-7** 쓰기 경로 신설: `POST /projects/:id/logs`, `POST /agents/:id/runs`, `PATCH /agent-runs/:id`. 호출 주체가 외부 에이전트이므로 사용자 세션이 아닌 **프로젝트 스코프 API 키**(`X-API-Key`)로 인증한다. `PROJECT_API_KEYS` 신설, 키는 해시로만 저장하고 발급 응답에서 1회만 원문 노출.

**B-2** `policy_passed` 상태 단일 기준. 그 상태는 **Trivy·Conftest 모두 pass일 때만**(AND) 부여하고, 하나라도 fail이면 `policy_blocked`. 승인 API는 개별 verdict를 다시 보지 않고 `build_status`만 검사한다 — 판정 로직을 한 곳에 가둔다.

**C-3** `DOCUMENTS.upload_status`(`pending`/`completed`) + `POST /documents/:id/complete`. `pending` 24시간 경과분은 정리 배치가 삭제.
