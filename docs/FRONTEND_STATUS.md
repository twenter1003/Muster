## 프로젝트를 가로지르는 조회

모듈 페이지 넷은 "내 모든 프로젝트를 한 번에" 보는 화면인데, 모든 조회가
`/projects/:id/...` 아래에만 있어서 만들 수가 없었다. 그래서 사이드바 링크 넷이
`준비 중`으로 죽어 있었다(모바일 하단 탭 로그까지 다섯).

서버에 조회 다섯을 새로 팠다 — `GET /documents` · `/agents` · `/env-configs` ·
`/logs` · `/health-snapshots`. 셋 다 지켜야 하는 규칙이 있다:

1. **범위를 먼저 좁힌다.** 요청자가 멤버인 프로젝트로 자른 뒤에 질의한다. 한 행만 새도
   남의 프로젝트 이름과 내용이 그대로 나간다. e2e가 응답 전문에 남의 문자열이 있는지까지 본다.
2. **`project_name`은 조인으로 실어 보낸다.** 범위 질의가 이미 `id→이름`을 가져오므로
   (`ScopedPage<T>`) 행마다 다시 읽지도, 클라이언트가 따로 조회하지도 않는다. 이 엔드포인트가
   존재하는 이유 자체가 그 N+1을 없애는 것이다.
3. **필터는 서버가 건다.** 클라이언트 필터는 현재 페이지 안에서만 걸려서, 걸리지 않은 목록을
   걸린 목록으로 읽게 만든다(감사 로그에서 겪은 문제다). 모르는 값은 400이다.

Ingest의 둘(`/logs`·`/health-snapshots`)은 Part 2 §8 때문에 다른 모듈을 부를 수 없어
스코프 질의를 `ingest/member-scope.ts`에 따로 둔다. 공용으로 빼지 않은 이유는 그 파일 주석에 있다.

## 만들지 않은 것과 이유

- **1b(상단 내비 + 칸반)** — 설계서가 셸을 1a로 확정하며 칸반만 목록의 보기 전환으로
  흡수했다. 칸반은 프로젝트 목록의 `?view=board`에 있다.
- **칸반 드래그 앤 드롭** — "카드를 옮기면 단계 전환이 기록된다"는 설계서 문구가 있으나
  이번 범위(기능 확인)를 넘는다.
- **설정의 알림 탭** — 저장할 백엔드가 없다. 동작하지 않는 폼은 고장으로 보인다.
- **멤버 탭** — 자리만 두고 "확장" 배지. 설계서 09가 "지금 만들면 쓸 사람이 없다"고 정했다.

## 공용 스타일

화면이 각자 복제하던 선언을 `styles/app.css`로 올렸다. 올린 기준은 **여러 화면이 실제로
똑같이 쓰던 것**뿐이고, 화면마다 다른 값(패딩·행 높이·최소 너비)은 화면 파일에 남겼다.

| 공용 | 역할 | 쓰는 화면 |
|---|---|---|
| `.meta` | 주 내용이 아닌 글 — 설명·빈 상태·라벨·각주 | 전부 |
| `.error-note` | 조회·저장 실패 상자 | 목록·알림·감사 |
| `.scroll-x` | 가로 스크롤을 여기서 멈춘다 | 표가 있는 화면 |
| `.page` · `.page__head` · `.page__count` | 목록형 화면의 세로 흐름과 제목 줄 | 목록·알림·감사 |
| `.chip-row` · `.chip` | 칩 줄과 토글 칩 | 목록·알림·감사·리포트·개요·환경 구성 |
| `.table` · `.card` · `.panel` · `.field` · `.input` | 표·카드·패널·폼 뼈대 | 해당 화면 전부 |

**올리지 않은 것도 있다.** 선언이 같아도 역할이 다르면 두었다 — `.audit__foot`(페이저 줄)은
`.page__head`와 선언이 같지만 이름이 자리를 말하지 않으면 다음 사람이 머리를 찾으러 간다.
`.plist__content`도 `.card__body`와 같지만 카드가 아니다.

결과: CSS 번들 41.9 kB → 35.0 kB.

## 두 자료의 충돌을 어떻게 다뤘나

`Muster Console.dc.html`(목업 1a~1j)은 **다크 Nocturne + 보라 액센트**이고,
UI/UX 설계서 v2.1은 그 색 체계를 **명시적으로 폐기**하고 잉크 그레이스케일 + 단일 신호색으로
바꿨다. 사용자 결정: **구조·정보 밀도는 목업, 색·타이포·배지 규칙은 설계서.**

## 설계서에서 발견한 오류

**다크 신호색 위 흰 글자가 안 읽힌다.** 설계서는 "배지의 채운 신호색 위 흰 글자가 가장
빠듯하다. 다크 매핑에서 신호색을 올린 이유이기도 하다"고 적었는데 **거꾸로다** — 색을 밝게
올리면 흰 글자 대비는 나빠진다. WCAG 공식으로 직접 계산한 값:

| 조합 | 실측 | 판정 |
|---|---|---|
| 라이트 `#8E1B1B` 위 흰 글자 | 9.04:1 | AAA |
| 다크 `#D98A8A` 위 흰 글자 | **2.64:1** | **미달** |
| 다크 `#D98A8A` 위 잉크 글자 | 6.86:1 | AA ✓ |

`--color-on-signal` 토큰을 신설해 다크에서 글자를 잉크로 뒤집었다. 설계서의 대비표 자체도
실측과 1~2포인트씩 다르다(본문/바탕 라이트 15.8 표기 → 실측 17.63).

**간격 규칙이 자기모순이다.** "4의 배수만 쓴다"고 선언하고 카드 내부 여백을 9로 적었다.
규칙이 개별 수치보다 상위라고 보고 12로 올렸다(8로 내리면 카드 사이 간격 8과 같아져
"여백 > 카드 간격" 관계가 무너진다).

**타입·간격 수치의 단위계가 명시돼 있지 않다.** 본문 6.2pt는 포스터 스케일 캔버스 값이라
웹에서 약 8px이 된다. 비율만 가져와 계수 k = 14px / 6.2pt = 2.2581로 환산했다
(25/17/14/12/11px). 시안 실측으로 맞추는 것이 남아 있다.

## 실행하고 나서야 잡힌 버그들

정적 검사로는 안 잡히고 **실제로 돌려야만** 드러난 것들이다.

1. **`apiFetch`가 204에서 터졌다.** 본문 없는 응답에 `res.json()`을 부르면 SyntaxError로
   죽는데, 그때 서버에서는 이미 삭제가 끝나 있다. 키 폐기·연동 해제가 "실패했다"고 뜨면서
   실제로는 지워지는 상태였다.
2. **`null` 반환이 본문 없는 200을 만든다.** 컨트롤러가 null을 돌려주면 Nest가 빈 본문을
   보내고 클라이언트가 거기서 터진다. `{ integration: null }`로 감쌌다.
3. **셸이 가로로 밀렸다.** 플렉스 자식의 기본 `min-width: auto`가 `<input>`의 고유 너비로
   잠겨 좁은 화면에서 상단바가 뷰포트보다 넓어졌다.
4. **e2e 스위트가 두 페이즈에 걸쳐 빨간 상태였다.** 단위 테스트만 돌리고 완료를 보고해 온
   탓이다. CHECK 제약 수는 Phase 4부터, 엔티티·테이블 수는 Phase 6부터 어긋나 있었다.

- **실행 어댑터가 없다** — 환경 구성이 `running`으로 가면 거기서 멈춘다. 실행을 끝내는

- **배포(Phase 7)** — 월 $10 상한이 걸려 있고, "남에게 보여주기"는 멤버 초대 API가
  먼저 있어야 성립한다 (멤버 화면은 읽기 전용이다)
