# 최신 LLM 모델 생태계 및 단가·스펙 가이드 (2026년 기준)

Muster는 개인용 프로젝트 모니터링 플랫폼으로서, 자체 백엔드(Gemini API 기반 진행률 분석 및 도커 설정 생성)와 외부 에이전트(Claude Code, Antigravity/Gemini, OpenAI 등)의 토큰 관제를 수행합니다.

이 문서는 **2026년 기준 주요 프론티어 LLM의 최신 라인업, 단가(Pricing), 컨텍스트 윈도우, 프롬프트 캐싱 메커니즘, 그리고 Muster 내부 활용 권장사항**을 정리한 통합 기술 가이드입니다. 세션이 바뀌거나 다른 AI 에이전트가 투입될 때 **낡은 모델명을 사용하거나 단가를 잘못 계산하지 않도록** 이 문서를 단일 원천으로 삼습니다.

## 3. 프롬프트 캐싱(Prompt Caching) 및 컨텍스트 팽창 대응

### 3.1 1M+ 대용량 컨텍스트 시대의 함정
- 최신 모델들은 모두 100만(1M) 토큰 이상의 초대형 컨텍스트 창을 지원합니다.
- 그러나 **대화 세션이 길어질수록 매 턴마다 누적된 전체 히스토리가 입력 토큰으로 다시 청구**되므로, 턴 수가 100회를 넘어가면 단일 세션에서 수백만~수천만 토큰이 소모됩니다.
- Muster 대시보드의 **"컨텍스트 팽창 낭비율"**은 다음 공식으로 측정됩니다:
  $$\text{Waste Rate} = \frac{\text{누적 입력 토큰} - (\text{마지막 턴 컨텍스트 크기})}{\text{총 사용 토큰}} \times 100\%$$

### 3.2 프롬프트 캐싱 절감 원리
- **Claude / Gemini**: 시스템 프롬프트, 도구 정의, 공통 가이드라인 문서 등 변하지 않는 앞부분을 캐싱하면 캐시 읽기 토큰 단가가 **정규 입력가의 10% 수준**으로 급감합니다.
- **Muster의 권장 패턴**:
  - `ProjectGoalsService` 진행률 분석 시: README 및 고정 프로젝트 문서는 프롬프트 앞단에 배치하여 캐시 히트율을 극대화.
  - 가변적인 커밋 메시지나 최근 로그는 프롬프트 최하단에 배치.

## 4. Muster 시스템 내부 구현 권장 사항

1. **`apps/api` 환경변수 기본값 (`env.schema.ts`)**:
   - `GEMINI_MODEL`: `gemini-3.6-flash` (검증된 안정 기본값) 또는 `gemini-3.7-flash` / `gemini-3.8-flash`.
   - 구버전인 `gemini-2.0-*`, `gemini-2.5-flash`를 기본값으로 되돌리지 말 것 (404 오류 발생).
2. **구조화 출력 (Structured Outputs)**:
   - Gemini API 호출 시 `generationConfig.responseMimeType: "application/json"`과 `responseSchema`를 활용하여 결정론적 JSON 파싱을 보장할 것.
   - 단, 모델이 스키마 범위를 벗어난 값(예: percent > 100)을 반환할 수 있으므로 백엔드 서비스 레이어에서 결정론적 재검증(Clamp / Filter)을 병행할 것.
3. **에이전트 토큰 관제 (`AGENT_RUNS`)**:
   - 토큰 집계 시 `input_tokens`, `output_tokens`, `cache_creation_input_tokens`, `cache_read_input_tokens` 4개 필드를 모두 수집하여 캐싱 절감 효과를 구분 파악할 것.
   - 단가 테이블(`docs/LLM_ECOSYSTEM_GUIDE.md`)을 기반으로 도구별 실소모 비용(USD)을 정확히 산출할 것.
