문서 올리고 관리하기

파일은 서버를 거치지 않고 클라우드 저장소로 바로 올라갑니다. 그래서 큰 파일도 빠릅니다.

파일 선택올릴 파일을 고릅니다. 고르면 아래에 이름과 크기가 표시됩니다.
업로드실제로 올립니다. 3단계(주소 발급 → 전송 → 완료 처리)가 자동으로 돌고, 끝나면 표에 completed로 나타납니다.
다운로드올린 파일을 내려받습니다. completed 상태일 때만 눌립니다 — 아직 전송 중이면 비활성입니다.
수정제목 · 종류 · 커밋 참조를 고칩니다. 파일 내용 자체는 바뀌지 않습니다(새 버전은 다시 업로드).
삭제문서를 지웁니다. 되돌릴 수 없습니다.
업로드가 503으로 실패한다면 서버에 저장소(GCS 버킷) 설정이 안 된 상태입니다. 배포할 때 GCS_BUCKET 값을 넣어야 켜집니다. 다른 기능은 그대로 동작합니다.

탭 · 환경 구성

“환경 구성”이 대체 뭔가요?

에이전트가 코드를 돌릴 실행 환경(Docker)입니다. 도커를 몰라도 됩니다 — 언어 · 프레임워크 · 데이터베이스를 고르면 Muster가 설정 파일을 대신 만들어 줍니다.

1

고른다

Python + FastAPI + PostgreSQL 처럼 클릭으로 고릅니다.

2

검사한다

Policy Gate가 위험한 설정(외부 포트 개방 등)을 자동으로 잡아냅니다.

3

승인한다

검사를 통과하면 승인하고 실행이 활성화됩니다.

4

빌드된다

GitHub Actions에서 실제로 이미지가 만들어지고 상태가 갱신됩니다.

상태(build_status)가 뜻하는 것

draft 작성 중 · approved 승인됨 · running 빌드 중 · succeeded 완료 · failed 실패

Policy Gate란

“이 설정이 안전한가”를 자동 검사하는 관문입니다. 걸리면 무엇이 왜 걸렸는지 화면에 이유가 나오고, 고치면 다시 통과합니다.

탭 · 환경 구성

환경 구성 화면의 버튼

새 환경 구성프로젝트 → 환경 구성 탭 맨 위. 여기서 만들기 화면으로 들어갑니다.
언어 · 프레임워크 · DB드롭다운으로 고릅니다. 고를 때마다 아래 위험도 설명과 Policy Gate 결과가 실시간으로 바뀝니다.
템플릿미리 만들어 둔 프리셋을 고릅니다. 비워 두면 “직접 작성”입니다. (다음 쪽)
저장아직 실행하지 않고 draft로만 저장합니다. 나중에 이어서 할 때.
승인하고 실행승인(approve)과 실행(execute)을 한 번에 합니다. 누르면 실제 빌드가 시작되고 상태가 running이 됩니다.
상태 전이 / 판정이 구성이 어떤 상태를 거쳐 왔는지, 왜 승인/거절됐는지의 기록. 실패했을 때 여기를 먼저 보세요.
“승인하고 실행”이 회색이라면 Policy Gate를 아직 통과하지 못한 것입니다. 그 위 검사 목록에서 빨간 항목의 이유를 읽고 설정을 고치세요.

EnvCatalog

환경 템플릿 쓰는 법

같은 구성을 여러 프로젝트에서 반복해서 만들 때 씁니다. 템플릿은 프로젝트가 아니라 계정에 달려 있습니다.

1

템플릿을 만든다

왼쪽 메뉴 EnvCatalog → 아래 “템플릿” 카드 → 이름 · 스택 · Dockerfile을 적고 생성.

2

프로젝트에서 고른다

프로젝트 → 환경 구성 탭 → 새 환경 구성 → 템플릿 드롭다운에서 방금 만든 것을 선택.

3

실행한다

검사를 통과하면 승인하고 실행. 이후는 직접 작성한 구성과 완전히 같습니다.

EnvCatalog 화면의 버튼

생성 — 새 템플릿 등록
삭제 — 템플릿 제거(이미 그 템플릿으로 만든 환경 구성은 그대로 남습니다)
상태 필터 — 전체 환경 구성을 build_status로 걸러 봅니다

템플릿이 꼭 필요한가요? 아닙니다. 프로젝트 하나만 쓸 거라면 건너뛰고 “직접 작성”으로 만드세요. 같은 구성을 세 번째 만들 때쯤 템플릿으로 빼면 됩니다.

에이전트 등록하고 실행하기

에이전트 등록이름만 있으면 등록됩니다. 설정(마크다운)은 비워 두고 나중에 채워도 됩니다 — 먼저 등록해서 돌려 보는 게 실제 순서입니다.
실행줄마다 하나씩 있습니다. 누르면 실행이 시작되고 아래에 실행 기록이 쌓입니다.
수정이름과 설정을 고칩니다. 건드리지 않은 칸은 전송되지 않아 다른 사람의 수정을 덮어쓰지 않습니다.
실행 결과 정정실행 기록의 상태·토큰·비용을 손으로 고칩니다. 외부에서 돌린 실행을 기록에 맞춰 넣을 때 씁니다. 비우면 그 칸은 안 바뀝니다.
삭제에이전트를 제거합니다. 실행 기록도 함께 사라집니다.
설정(config_md)에 뭘 적나요? 이 에이전트가 무슨 역할인지, 어떤 규칙을 지켜야 하는지를 마크다운으로 적습니다. 비워 둬도 등록과 실행에는 지장이 없습니다.

예산과 알림

에이전트를 돌리면 토큰과 비용이 쌓입니다. 한도를 정해 두면 넘기 전에 알려 줍니다.

어디서 보나

프로젝트 → 에이전트 탭 오른쪽 예산 카드. 이번 달 사용량과 한도 대비 비율이 막대로 나옵니다.

어디서 정하나

왼쪽 메뉴 설정 → 예산 탭. 월 토큰 한도, 월 비용(USD) 한도, 경고 기준(%)을 정합니다.

토큰 한도 (월)이번 달 쓸 수 있는 토큰의 상한. 비워 두면 한도 없음입니다.
비용 한도 (USD)이번 달 쓸 수 있는 금액의 상한.
경고 기준 (%)예: 80으로 두면 한도의 80%를 넘는 순간 알림 메뉴에 경고가 들어옵니다.
저장한도를 적용합니다. 즉시 반영됩니다.

부록

용어 한 줄 정리

  • 프로젝트 — 모든 것이 담기는 그릇. 여기서 시작합니다.
  • 문서(Document) — 프로젝트에 올린 파일. 제목·종류·버전이 붙습니다.
  • 환경 구성(Env Config) — 코드를 돌릴 Docker 실행 환경 한 벌.
  • 템플릿(Env Template) — 환경 구성을 만들 때 쓰는 프리셋. 계정 단위.
  • Policy Gate — 환경 구성이 안전한지 자동 검사하는 관문.
  • build_status — 환경 구성의 상태. draft / approved / running / succeeded / failed.
  • 에이전트(Agent) — 등록해 두고 실행하는 AI 작업자.
  • 실행(Run) — 에이전트를 한 번 돌린 기록. 토큰·비용·상태가 남습니다.
  • 예산(Budget) — 프로젝트별 월 토큰·비용 한도.
  • 헬스(Health) — 프로젝트 건강도 점수. 낮으면 이유가 함께 표시됩니다.
  • DORA 지표 — 배포 빈도·리드 타임·변경 실패율. 개발 속도와 안정성의 척도.
  • 감사 로그(Audit) — 누가 언제 무엇을 했는지의 지울 수 없는 기록.
기억할 한 가지 — 헷갈리면 프로젝트 목록 → 프로젝트 열기로 돌아가세요. 만드는 일은 전부 그 안의 탭에 있습니다.
